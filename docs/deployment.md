# Azure deployment

The Bicep template provisions ACR, Linux App Service, PostgreSQL Flexible Server, Key Vault, Log Analytics, Application Insights, a virtual network, private PostgreSQL DNS, and a system-assigned managed identity. In production, PostgreSQL public access is disabled, the server uses a delegated database subnet, and App Service routes through its delegated integration subnet. Development and test retain the `AllowAzureServices` rule for bootstrap convenience only. The web identity receives ACR pull and Key Vault secrets-user roles. The database connection string is stored as a Key Vault secret, requires full TLS certificate verification, and is injected into App Service through a Key Vault reference.

App Service storage is enabled and Data Protection keys are persisted under `/home/data-protection-keys`. This keeps login cookies and encrypted SMTP passwords valid across container restarts and image updates. For Docker Compose, the equivalent `/app/keys` path is mounted as the `web-keys` named volume. Treat both locations as sensitive application state and back them up with the database.

The deployment templates enable forwarded `X-Forwarded-For` and `X-Forwarded-Proto` handling because traffic terminates at the trusted App Service or Compose proxy. Do not enable `ForwardedHeaders__TrustAll` when exposing the API directly to untrusted clients; use explicit known proxy/network configuration instead.

GitHub Actions authenticates with OIDC. Create an Entra application or user-assigned identity with a federated credential restricted to the repository/environment and grant only the target resource group's deployment permissions plus role-assignment rights where required.

Configure GitHub environment variables: `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, `AZURE_RESOURCE_GROUP`, `AZURE_LOCATION`, `AZURE_ACR_NAME`, `AZURE_WEBAPP_NAME`, and `POSTGRES_ADMIN_LOGIN`. Configure `POSTGRES_ADMIN_PASSWORD` and `SEED_ADMIN_PASSWORD` as environment secrets and pass both secure values to the Bicep deployment. The web app no longer falls back to the local development administrator password in Azure. Prefer moving bootstrap secrets to a protected deployment secret store after provisioning.

Production startup fails closed when the database connection is missing, `AllowedHosts` is unrestricted, or the bootstrap administrator password is missing/default. Deployments are manual, serialized per environment, and run frontend, backend, container, and Bicep verification before activation. Configure required reviewers on the GitHub `prod` environment.

Production startup applies checked-in EF Core migrations before role/user seeding. Development retains `EnsureCreated` and compatibility DDL so existing local volumes continue to work. Every production schema change must be represented by a reviewed migration; never grant the application arbitrary schema changes outside this migration path.

The initial migration expects either an empty production database or a database already tracked by EF migrations. If upgrading a database previously created by `EnsureCreated`, first back it up and verify a restore, compare it with `202608270001_InitialProductionSchema`, and insert that migration ID into `__EFMigrationsHistory` only after confirming the schemas match. Do not run the initial migration against an unbaselined populated database because it intentionally fails instead of overwriting existing tables.

Azure PostgreSQL Flexible Server network mode is selected when the server is created. An existing public production server cannot be converted in place by this template. Provision a new private server, migrate and validate the data, update the Key Vault connection-string secret, then retire the public server after the rollback window.
